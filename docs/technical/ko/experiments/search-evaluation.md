# 검색 평가: search-v1

[한국어](./search-evaluation.md) | [English](../../en/experiments/search-evaluation.md)

측정일: 2026-09-22

검색 도구를 계속 같은 기준으로 비교하기 위한 첫 개발용 평가다. 벡터 모델,
LangChain, 외부 API와 Codex 모델 호출을 사용하지 않는다.

## 평가 자료와 단위

- [dataset.json](../../../../evals/search/dataset.json): 광학·AI·소프트웨어 분야의
  합성 PDF 3개, 합성 대화 6개, 고정 질문 20개. 공개 논문 정확도 평가가 아니다.
- 실행기가 PDF를 임시 폴더에 실제로 생성하고 기본 변환기를 실행한다. 원본 PDF의
  전후 해시가 같은지 확인하며, 개인 자료원이나 개인 설치 설정을 변경하지 않는다.
- 질문은 정확한 용어, 한영 검색, 과거 대화, 여러 자료 비교, 다른 표현, 답 없음으로
  구분한다. 자연어 질문과 고정 검색어·범위를 함께 기록한다.
- 정답은 문서 ID와 그 안의 근거 구절이다. 문서만 맞고 필요한 내용이 없으면
  정답으로 세지 않는다. 일부 구절을 보여주는 도구의 특성까지 평가하기 위한 기준이다.
- 이 세트는 개발 중 확인·조정에 사용했다. 별도로 보관한 미사용 검증 세트가 아니며,
  실제 연구 자료의 검색 성능이나 Codex의 검색어 선택·최종 답변 품질을 증명하지 않는다.

## 계속 사용할 지표

| 지표 | 계산 기준 |
| --- | --- |
| Recall@10 | 상위 10개에 포함된 정답 근거 수 / 지정한 정답 근거 수. 같은 근거는 한 번만 계산 |
| MRR@10 | 상위 10개에서 첫 정답 순위의 역수. 없으면 0 |
| Precision@10 | 상위 10개 중 정답 근거가 있는 결과 수 / 10. 반환이 10개 미만이어도 분모는 10 |
| 답 없음 빈 결과율 | 답이 없는 질문에서 아무 결과도 반환하지 않은 비율 |
| 검색 범위 위반 | PDF 전용·대화 전용 요청에 섞인 다른 종류의 결과 개수 |
| 검색 시간 | 질문별 반복 측정의 중앙값을 계산한 뒤 질문 전체 평균. PDF 변환 시간 제외 |
| 반환 글자 수 | 반환한 `text` 길이의 합. JSON 메타데이터·추가 읽기·모델 토큰 수는 포함하지 않음 |

앞의 품질 지표는 답이 있는 18개 질문의 평균이다. 답이 없는 2개는 별도 집계한다.
정답이 한두 개뿐인 질문이 많아 Precision@10의 절대값은 낮다. 이를 단독으로
합격률이나 최종 답변 정확도로 해석하지 않는다. 반복 구절은 Precision에 포함될 수
있으므로 Recall과 중복·분배 회귀 테스트를 함께 확인한다.

평가 자료의 내용·정답을 바꾸면 버전을 올리고 비교 기준도 다시 측정한다.
실행기는 데이터 해시가 다른 보고서끼리 비교하지 않는다. 전체 평균과 질문별·유형별
결과를 함께 보며, 일부 유형의 악화를 전체 평균으로 숨기지 않는다.

## 이번 결과

기존 검색 코드와 개선 코드에 같은 자료·검색어·최대 10개 제한을 적용했다.
각 질문을 5회 실행했다. 기존 코드는 범위 옵션이 없어 통합 검색으로 실행했으며,
그로 인한 다른 자료 종류의 혼입도 범위 위반에 포함한다.

| 지표 | 기존 검색 | 개선 검색 |
| --- | ---: | ---: |
| Recall@10 | 0.944444 | 0.972222 |
| MRR@10 | 0.680556 | 1.000000 |
| Precision@10 | 0.150000 | 0.155556 |
| 답 없음 빈 결과율 | 1.000000 | 1.000000 |
| 검색 범위 위반 | 12 | 0 |
| 평균 검색 시간 | 2.599 ms | 4.706 ms |
| 평균 반환 글자 수 | 124.4 | 148.3 |

질문별 Recall·MRR·Precision이 기존보다 낮아진 사례는 없었다. `q01`처럼
`laser` 한 단어로 특정 PDF의 열 드리프트 구절까지 요구하면 상위 10개에서 그
구절을 놓칠 수 있다. 대화는 다시 나타나지만 의미 검색의 한계까지 해결한 것은 아니다.
자료 전체를 읽고 해시와 후보 분배를 처리하므로 검색 시간과 반환 분량은 늘었다.
이 시간은 작은 합성 자료를 같은 Mac에서 측정한 참고값이며 성능 보장이나 부하
시험 결과가 아니다. 큰 자료에서의 메모리·검색 시간·쓰기 잠금 대기는 추가 측정한다.

원시 기록에는 질문별 결과·반환 문서·자료 해시·검색 코드 해시가 들어 있다.

## 다시 측정하기

저장소 루트에서 실행한다. 평가 자료는 임시 공간에 생성하고 종료 시 정리한다.

```sh
.venv/bin/python -B scripts/evaluate-search.py \
  --repeat 5 \
  --compare evals/search/results/baseline-v1.json \
  --output /tmp/research-search-evaluation.json
```

다른 버전의 체크아웃을 평가하려면 `--code-root /path/to/checkout`을 추가한다.
`--output`을 생략하면 JSON을 화면에 출력한다. 기본 평가에는 모델 호출이 없다.

기능 회귀 테스트는 다음 명령으로 실행한다.

```sh
.venv/bin/python -B -m unittest discover -s tests -p 'test_search*.py'
```

다음 단계는 별도의 실제 연구 질문 세트로 일반화 여부를 확인하고, Codex가 질문에서
검색어와 범위를 선택하는 흐름을 따로 평가하는 것이다. 표현이 달라 놓치는 사례가
반복되면 같은 지표로 키워드·벡터 혼합 검색을 비교한다.
