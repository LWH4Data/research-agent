# 안전성과 에이전트 라우팅 검증

[한국어](./safety-routing-validation.md) | [English](../../en/experiments/safety-routing-validation.md)

검증일: 2026-09-22 · 백그라운드 검토: 2026-09-24 · 검토 노트 저장 감사: 2026-09-25

이 기록은 프로토타입 배포 전에 발견한 저장 복구, 권한, 프롬프트 주입과 모델
라우팅 문제를 실제 실행으로 확인한 범위를 남긴다.

## 확인한 결과

- 대화 저장·수정·삭제는 작업 저널과 프로세스 간 잠금을 사용한다. 파일 반영
  전후 하위 프로세스 `os._exit`, 파일 교체·동기화 오류와 같은 revision의 동시
  수정을 주입한 테스트에서 다음 작업이 승인된 변경을 이어서 완료했고 부분 상태를
  반환하지 않았다.
- 저장 원문의 LF, CRLF와 단독 CR 줄바꿈이 그대로 복원됐다.
- PDF 한 개마다 동기화 상태를 확정해 다음 PDF의 긴 변환 중에도 대화 쓰기를
  완료했다. 별도의 `sync.lock`은 동기화 작업 두 개가 동시에 실행되지 않도록
  직렬화하며, 긴 변환 중에는 대화 저장을 막지 않는다.
- PDF 동기화와 페이지 검토 저장은 `document_operations` 저널을 사용한다. Markdown
  교체 직후 하위 프로세스를 `os._exit`로 종료한 테스트에서 다음 동기화 또는 검토
  관련 명령이 SQLite와 Markdown을 목표 상태로 한 번만 이어서 완료했다. 예상하지
  못한 파일이나 DB 상태는 자동으로 덮어쓰지 않고 오류로 중단한다.
- 첫 실제 권한 E2E에서는 전용 설정에 최상위 `default_permissions`가 없어 설정
  로드가 실패했고, launcher가 프로젝트 루트를 작업 디렉터리로 사용해 그곳의
  기존 `sandbox_mode`가 permission profile보다 우선할 수 있음을 발견했다.
  `default_permissions = "research-store"`를 추가하고 `CODEX_HOME`과 `-C`를 같은
  전용 샌드박스 설정 디렉터리로 분리한 뒤 회귀 테스트를 다시 실행했다. 내부
  저장은 성공했고 외부 원본과 프로젝트 코드 쓰기는 차단됐다. 빈 임시 HOME의
  현재 Mac에서 설치와 제거도 완료됐다.
- 실행·삭제 지시를 넣은 PDF와 저장 대화를 동기화·시각 검토·검색했다. 지시는
  자료로만 처리됐고 원본 해시, 저장 대화와 등록 원본 목록은 바뀌지 않았다.
- 실제 Codex 호출은 **주 Codex → Luna 관리자 → 주 Codex → Sol 변환기 → 주
  Codex → Luna 관리자** 순서로 완료됐다. Luna 관리자가 Sol을 중첩 호출하는
  방식은 지원되지 않았다. 이는 백그라운드 검토 이전의 직접 호출 실험이다.
- 별도 Luna xhigh Codex 세션에서 JSONL 진행 이벤트를 한 번만 실행해 확인했다.
  `1/3`은 명령 완료 전에 전달됐고, 더 짧게 이어진 `2/3`, `3/3`과 완료 이벤트는
  같은 실행이 끝난 직후 한 묶음으로 전달됐다. 빠른 작업에서 보지 못한 중간
  상태를 만들거나 진행 표시 확인을 위해 작업을 재실행하지 않도록 지침을 보강했다.

## 2026-09-24 백그라운드 검토 확인

- 제한된 `research-review-worker` 프로필 안에서 합성 이미지 1쪽을 Sol high로
  처리하고, 지정된 JSON 형식의 페이지 결과를 받았다. 실제 논문 수식·표의
  정확도 확인을 대신하는 실험은 아니다.
- 분리 작업 시작, 문서 범위 병합, 완료 상태 조회, 일부 페이지 저장 뒤 실패·재시작,
  임시 렌더 이미지 정리와 무관한 폴더 보존을 가짜 모델 통합 테스트로 확인했다.
- macOS에서는 제한 프로필 안에서 두 번째 `codex sandbox`를 시작하면
  `sandbox_apply: Operation not permitted`가 발생했다. 검토기를 하나의 프로필로
  실행하고 그 안에서 프로젝트 소유 저장 명령을 직접 호출하도록 고쳤다. 설치본의
  상태 조회가 정상 동작했으며, 기존 대기 33쪽은 실행하지 않고 보존했다.
- 전체 자동 테스트는 292개 통과, 4개 건너뜀이다. 원본 쓰기 거부는 실제
  권한 통합 시험에서도 확인했다. 다만 현재 Codex 대화에서 새 명령 허용 규칙을
  재시작 없이 읽는지와 실제 논문 전체 검토의 정확도·사용량은 별도 검증이 필요하다.

## 2026-09-25 검토 노트 저장 감사

2026-09-25 개인 설치 저장소의 읽기 전용 감사에서는 문서 5개, `verified` 페이지
66개 모두에 비어 있지 않은 페이지별 Markdown 노트 66개가 대응했다. 저장된 문서
식별자·SHA-256·상태·모델·검토 시각과 관리 구역이 일치했고, 모든 현재 대기 목록은
비어 있었다. 누락·빈 노트·중복·불일치·고아 노트와 미완료 문서 저널은 0건이며
SQLite `quick_check`도 통과했다. DB·설정·Markdown 5개의 총 7개 파일은 감사 전후
SHA-256이 같았다. 이 저장소에는 이 조건에 따른 마이그레이션이 필요하지 않았다.

감사 범위는 해당 개인 설치본의 DB와 Markdown 대조다. 과거 테스트·개발 복사본,
원본 PDF 재해시, 실제 이미지 열람과 노트의 의미상 정확성은 확인하지 않았고 새
모델 호출도 하지 않았다. 다른 저장소의 과거 기록까지 정상이라는 뜻은 아니다.

2026-09-25 검증 기록: 전체 테스트 318개 중 313개가 통과하고 환경 의존 테스트
5개는 건너뛰었다. 설치본에서도 핵심 회귀 테스트 3개가 통과했다. 이 검증에서는
새 모델 호출을 수행하지 않았다.

재현 시 [배포 워크플로](../../../../.github/workflows/release-check.yml)의 허용 목록

## 직접 다시 보기

저장소 루트에서 다음 명령을 실행하면 원본 연구 파일이나 개인 등록을 바꾸지 않고
핵심 복구·동시 실행·장애 주입 검증을 다시 볼 수 있다.

```sh
./scripts/reproduce-validation.sh core
```

전체 자동 테스트는 `core` 대신 `full`을 사용한다. 실제 권한 프로필 검증은 일반
macOS 터미널에서 `./scripts/reproduce-validation.sh permission`으로 별도 실행한다.
권한 검증이 만드는 임시 원본과 확인 파일은 테스트 종료 시 정리된다.

실제 Luna→Sol 호출은 구독 사용량을 소비하고 활성 개인 등록을 일시적으로 바꿔야
하므로 이 반복 실행 명령에는 포함하지 않았다. 위 결과는 격리된 저장소 사본으로
수행한 실제 호출 기록을 기준으로 한다.

## 해석과 남은 범위

하위 에이전트는 부모 턴의 현재 권한 모드와 `/permissions`, `--yolo` 같은 실행
중 변경을 다시 적용받을 수 있다. 따라서 에이전트 TOML의 `read-only` 기본값은
Full access 부모 아래에서 강제 경계가 아니다. 이 기록의 권한 검증 결과는 제한된
저장 명령과 읽기 전용 부모를 사용한 흐름의 범위로 해석한다. 현재 사용 정책은
`Ask for approval`·`Approve for me` 사용 허용과 Full access 사용 금지이며,
부모 읽기 전용은 추가 보호를 위한 선택이다. 두 승인 모드의 실제 부모·자식 권한과
승인 예외까지 이 실험에서 모두 검증한 것은 아니다. 근거는 공식
[Codex 하위 에이전트 문서](https://learn.chatgpt.com/docs/agent-configuration/subagents)에
있다.

permission profile은 베타이고, 불러온 설정 중 하나라도 기존 `sandbox_mode`를
포함하면 기존 샌드박스 설정이 선택될 수 있다. 이번 회귀 테스트가 전용 설정
스택을 따로 둔 이유이며, Codex가 업데이트되면 공식
[권한 프로필 문서](https://learn.chatgpt.com/docs/permissions)와 실제 통합 테스트를
함께 다시 확인해야 한다.

이번 프롬프트 주입 실험은 한 개의 통제된 시나리오가 통과했다는 뜻이다. 가능한
모든 악성 문서에 대한 방어를 보장하지 않으므로 다른 지시 표현, 숨은 텍스트와
복합 문서에 대한 실험은 계속 필요하다.

빈 임시 HOME 테스트는 설치 흔적이 없는 사용자를 현재 Mac에서 재현했다. 실제
새 Mac에서 개발 도구 설치부터 비개발자가 완료하는 UX는 아직 확인하지 않았다.

대화 수명 주기와 PDF 동기화·시각 검토 저장에는 각각의 저널과 잠금이 적용된다.
강제 종료 검증은 별도 하위 프로세스에 주입한 `os._exit`를 사용했으며, 실제 Mac의
전원을 끄거나 저장 장치 장애를 발생시킨 실험은 아니다. PDF 수식·표·그림의
정확도와 Plus·Pro 사용량 측정도 이 검증의 범위에 포함하지 않았다.
진행 표시 통합 테스트의 작업별 토큰 수는 별도
[구독 사용량 실험 기록](./subscription-usage.md)에 예비 측정으로 남겼다.
