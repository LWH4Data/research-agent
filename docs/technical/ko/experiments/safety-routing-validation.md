## 2026-09-28 소개 응답의 가독성과 다음 행동

사용자가 제공한 실제 소개 응답은 기능을 긴 문단에 나열하고, 이미 선택한
스킬을 다시 선택하라고 안내했다. 스킬의 설명 분기에 기능 목록과 바로 보낼
요청 예시, 이미 확인한 상황을 반영하는 기준을 추가했다. README의 기능 설명과
기존 가이드 캡처는 유지했다.

대화 이력을 전달하지 않은 별도 에이전트에 처음 소개, 이미 9개 PDF가 저장된
상황의 다음 사용법, 영어 PDF의 한국어 질문 지원 여부를 각각 제시했다.
소개는 기능 목록과 첨부 요청 예시, 저장 후에는 검색 요청 예시, 특정 기능은
해당 설명만 반환했다. 설치·스킬 선택을 반복하거나 저장·조회 명령을 실행하지
않았다. 다만 평가 에이전트가 README 전체를 읽어 필요한 절만 읽는 기존 기준은
이번 평가에서 지키지 못했다. 응답 구성 확인과 읽기 범위 준수를 구분한다.
이후 사용자가 제공한 실제 재시험 화면에서 한 줄 소개, 기능 목록, PDF 첨부
요청 예시를 확인했다. 스킬 재선택 안내도 없었다. 원본 캡처(1584×722)를
웹 가이드 4단계에 반영했다. 이는 답변 구성 확인이며 읽은 파일의 범위나
저장·시각 검토의 성공을 증명하지 않는다. 표시된 14초는 이 실행의 기록이다.

## 2026-09-28 실제 제한 환경의 시각 검토 시작 실패 수정

개인 설치본의 폴더 저장 시험에서 PDF 9개 텍스트 저장은 완료됐지만, 96쪽의
시각 검토는 모두 대기 상태였다. 9개 문서 연결에 `Cannot verify execution
supervisor`가 기록돼 있었고 활성 실행은 없었다. 현재 환경에서 기존
`/bin/ps` 실행이 `Operation not permitted`로 거부되는 것을 재현했다.
이 실행 파일은 setuid이며, 같은 제한 환경에서 직접 `libproc`로 자기/자식
프로세스 정보를 조회하는 것은 허용됐다.

- macOS 식별 조회를 `proc_pidinfo(PROC_PIDTBSDINFO)`로 교체했다. PID·그룹·
  생성 초/마이크로초와 반환 레코드를 검증하며 권한 프로필은 변경하지 않았다.
- 조회 거부·잘못된 레코드를 실제 프로세스 종료와 구분한다. 조회 실패로 다른
  프로세스에 종료 신호를 보내거나 실행 소유권을 해제하지 않는다. 모델 시작 전
  확인 실패에서는 입력 게이트를 닫고 자식 종료를 확인하며 진단을 보존한다.
- 집중 테스트 **27개**와 알림/배포/감독 회귀 테스트 **22개**가 모두 통과했다.
  이전 `/bin/ps` 실패로 건너뛰던 실제 프로세스 감독 8개가 이번에는 통과했다.
- 별도 통합 테스트에서 **실제 Codex `research-review-worker` 프로필**을 적용한
  임시 제품본으로 감독 8개를 다시 실행해 건너뜀 없이 통과했다. 테스트 원본 쓰기
  차단과 내용·inode·수정 시각·권한 유지도 확인했다. 가짜 모델만 사용했다.
- 독립 검토자가 같은 실제 프로필로 띄운 서로 다른 두 실행기에서 살아 있는
  프로세스 식별 결과가 일치함을 확인했다. 권한 확대나 실제 모델 호출은 없었다.
- 가이드 일치·변경 파일 검사를 통과했다. `permission` 재현 모드에 새 통합 검사를
  포함했다. 전체 테스트나 실제 Sol 변환·알림 수신·새 Mac 설치를 이번에 다시
  확인한 것은 아니다.

기존 검증은 감독 테스트가 현재 샌드박스에서 건너뛰어졌고, 권한 통합은 파일
쓰기만 확인했기 때문에 이 결함을 잡지 못했다. 설치본의 실행기 파일 하나를
백업 후 교체했다. 이미 저장한 9개 PDF와 대기 페이지는 재사용하며 자료·원본·
설정의 내용·메타데이터 일치와 설치본의 네이티브 조회 성공을 확인했다. 실제
시각 검토 재개는 사용자 시험 단계로 남긴다.

```sh
.venv/bin/python -B -m unittest discover -s tests -p 'test_process_identity.py' -v
.venv/bin/python -B -m unittest discover -s tests -p 'test_lifecycle_*.py' -v
# 일반 터미널에서 실행; 임시 제품본/자료와 가짜 모델만 사용
RESEARCH_AGENT_RUN_SANDBOX_TEST=1 .venv/bin/python -B -m unittest tests.test_process_identity_integration -v
```

## 2026-09-28 폴더 확인 후 자동 저장 검증

**개발본 검증이며 개인 설치본·공개 v0.3.0을 갱신하지 않았다.** 최종 폴더 확인이
정확한 자료원 등록과 텍스트 저장·시각 검토 접수로 이어지도록 연결했다. 기존
자료원 등록의 `added`는 유지하고 이번 처리 범위인 `selected`를 별도로 반환한다.

- 독립 검토자가 선택·전달·설치 안내·네이티브 창·접수 테스트 **86개**를 확인했다.
  취소 시 실행 없음, 기존 폴더 재선택, 미선택 폴더 제외, 한 번의 접수, 실행기 없는
  설치의 저장 보류, 제한 실행기 실패 시 우회 없음이 포함된다.
- 검토 중 재개 정보가 설치 안내의 출력 수집에 가려지는 문제와 잘못된 접수 응답
  형태를 수정했다. 접수 키·명세는 저장 전부터 전달되고, 중단 시 이미 저장이
  시작됐을 수 있음을 알린다. 수정 영향 27개 재실행과 잘못된 응답 추가 확인을 통과했다.
- 실제 제품 목록으로 만든 폐기 가능한 압축을 풀어 공개 `source-add`를 실행했다.
  두 폴더 신규 선택·역순/중복 재선택에서 정확한 문서만 저장하고 다른 등록 폴더는
  읽지 않았다. 전체 검토 보류에서 텍스트 저장은 완료되고 시각 시도는 0회였다.
  원본의 내용·항목·inode·권한·수정 시각을 그대로 유지했다. 이 검사는 가짜 Codex
  실행기를 사용하며 실제 샌드박스 강제력·모델 실행의 증거는 아니다.
- 최종 전체 **493개 중 478개 통과·15개 건너뜀**. 건너뜀은 권한 통합 3개,
  OS 프로세스 소유권 조건 8개, 압축 환경 변수 조건 2개, 대소문자 구분 조건 2개다.
  압축 내용 검사는 따로 실행해 통과했다. 실제 새 Mac/다운로드 설치·모델 호출·
  알림 수신·사용자 창 클릭은 이번 검증에 포함하지 않았다.
- 실제 릴리스 워크플로의 조립 코드를 실행해 **제품 파일 58개**를 확인했고,
  제품 목록·압축 내용 2개 검사, 버전·한영 설치 명령·가이드 검사와 JavaScript
  구문 검사를 통과했다. 공개 태그·배포 파일은 변경하지 않았다.

재현은 개발 저장소에서 다음과 같다. 모든 입력과 저장소는 임시 경로다.


위 자동 검증 이후 사용자가 재시험 준비 1–3단계를 승인했다. 기존 검토가 끝나고
잠금이 해제됐음을 확인해 전체 설치본·개인 등록을 백업했으며, 자료·상태 디렉터리는
삭제하지 않고 백업으로 옮겼다. 개발본 제품 파일을 같은 설치 경로에 적용하고
기존 Python 환경을 재사용했다. 보호된 프로젝트 `.codex/config.toml`은 TOML 값이
최신 제품 설정과 같고 주석만 달라 유지했다. 개인 등록 갱신 후 실제 공개 실행기의
자료원 0개·검토 요청 0개·실행 없음·전체 보류 해제와 DB 스키마 5·문서/대화 0건을
확인했다. 원본 4개 위치의 내용·inode·권한·수정 시각은 유지됐다. 실제 PDF 저장·
모델 호출·새 Mac 설치를 확인한 결과는 아니다.

다음 실제 사용 확인은 사용자가 새 버튼으로 확정한 뒤 텍스트 저장 결과와 검토
인계를 확인하는 것이다. 기존 확인 목록 캡처에는 이전 버튼 문구가 남아 있으므로
가이드에 그 사실을 표시했다. 초기화 전 자료는 로컬 백업에서 복원할 수 있다.

## 2026-09-28 시각 검토 수명 구현 검증

사용자 결정에 따라 **시간·페이지 기준으로 자동 중단하는 경로는 제거**했다.
기준을 설정한 경우 안내만 보내고, 사용자 중단 요청이나 권한·실행 오류가 없는
한 검토를 계속한다. 기본 시간·페이지 상한은 없으며 실제 토큰 정보가 없는
실행은 미측정으로 남긴다. 구독 잔여 퍼센트나 정확한 비용을 계산하지 않는다.

별도 작업 공간에서 구현·저장소 담당을 나누고, 코드를 작성하지 않은 검토자가
반복 검토와 최종 테스트를 담당했다. 아래는 개발 구현의 결과이며 v0.3.0 배포나
`~/research-agent` 설치본 갱신의 증거가 아니다.

| 검증 대상 | 재현한 조건과 확인 내용 |
| --- | --- |
| 독립 접수와 공유 실행 | 동일 문서 A/B, 일부 페이지 겹침, 한 요청 내 중복 항목의 범위 합집합. A 취소 후 B의 유효한 페이지 결과는 보존 |
| 텍스트→검토 연결 | 안정적인 키로 접수 후 첨부 전달·텍스트 확정·정확한 버전 연결·실행 인수. 여러 입력 중 하나가 대기면 조기 완료하지 않음 |
| 중단과 실행 소유권 | 가짜 모델을 실제 하위 프로세스로 실행. 제어 부모 종료·감시자 종료·명시적 취소·PID 생성 정보 불일치에서 중복 실행 및 오종료 방지 |
| 저장 경계 | 저널 확정과 페이지별 권한 검사. 현재 버전의 검증 노트만 완료 근거로 사용. 본문 저장 직후 연결 전 종료에서도 접수 결과 복구 |
| 삭제와 재시도 | 두 첨부 중 하나 삭제 후 같은 키 재시도, 복사 중 삭제, 텍스트 확정 후 연결 전 삭제에서 삭제한 자료를 자동 재생성하지 않음 |
| 만료·정리 | 기한을 키에 포함해 거부 기록 정리 후에도 옛 키 재사용 거부. 임시 이미지 소유 목록으로 정리하고 완료 노트와 원본은 유지 |
| 알림 | 저장 잠금·저널 복구 없이 알림 영역만 갱신. 실패 재시도 제한, 동시 취소 보존, 짧은 작업의 지난 25% 알림 재전송 방지. 안내 실패가 실행을 중단하지 않음 |
| 배포 파일 | 실제 배포 목록으로 만든 압축에서 공개 실행기 로딩·등록 소유권 거부·전체 보류 유지·첨부 두 개 저장을 확인. 원본 내용과 디렉터리 항목 유지 |

검토 중 발견한 예약 공개 전 잠금 공백, A 취소로 B 결과까지 버리는 오류,

## 확인한 결과

- 대화 저장·수정·삭제는 작업 저널과 프로세스 간 잠금을 사용한다. 파일 반영
  전후 하위 프로세스 `os._exit`, 파일 교체·동기화 오류와 같은 revision의 동시
  수정을 주입한 테스트에서 다음 작업이 승인된 변경을 이어서 완료했고 부분 상태를
  반환하지 않았다.
- 저장 원문의 LF, CRLF와 단독 CR 줄바꿈이 그대로 복원됐다.
- PDF 한 개마다 동기화 상태를 확정해 다음 PDF의 긴 변환 중에도 대화 쓰기를
  완료했다. 별도의 `sync.lock`은 동기화 작업 두 개가 동시에 실행되지 않도록
  직렬화하며, 긴 변환 중에는 대화 저장을 막지 않는다.
- PDF 동기화와 페이지 검토 저장은 `document_operations` 저널을 사용한다. Markdown
  교체 직후 하위 프로세스를 `os._exit`로 종료한 테스트에서 다음 동기화 또는 검토
  관련 명령이 SQLite와 Markdown을 목표 상태로 한 번만 이어서 완료했다. 예상하지
  못한 파일이나 DB 상태는 자동으로 덮어쓰지 않고 오류로 중단한다.
- 첫 실제 권한 E2E에서는 전용 설정에 최상위 `default_permissions`가 없어 설정
  로드가 실패했고, launcher가 프로젝트 루트를 작업 디렉터리로 사용해 그곳의
  기존 `sandbox_mode`가 permission profile보다 우선할 수 있음을 발견했다.
  `default_permissions = "research-store"`를 추가하고 `CODEX_HOME`과 `-C`를 같은
  전용 샌드박스 설정 디렉터리로 분리한 뒤 회귀 테스트를 다시 실행했다. 내부
  저장은 성공했고 외부 원본과 프로젝트 코드 쓰기는 차단됐다. 빈 임시 HOME의
  현재 Mac에서 설치와 제거도 완료됐다.
- 실행·삭제 지시를 넣은 PDF와 저장 대화를 동기화·시각 검토·검색했다. 지시는
  자료로만 처리됐고 원본 해시, 저장 대화와 등록 원본 목록은 바뀌지 않았다.
- 실제 Codex 호출은 **주 Codex → Luna 관리자 → 주 Codex → Sol 변환기 → 주
  Codex → Luna 관리자** 순서로 완료됐다. Luna 관리자가 Sol을 중첩 호출하는
  방식은 지원되지 않았다. 이는 백그라운드 검토 이전의 직접 호출 실험이다.
- 별도 Luna xhigh Codex 세션에서 JSONL 진행 이벤트를 한 번만 실행해 확인했다.
  `1/3`은 명령 완료 전에 전달됐고, 더 짧게 이어진 `2/3`, `3/3`과 완료 이벤트는
  같은 실행이 끝난 직후 한 묶음으로 전달됐다. 빠른 작업에서 보지 못한 중간
  상태를 만들거나 진행 표시 확인을 위해 작업을 재실행하지 않도록 지침을 보강했다.

## 해석과 남은 범위

하위 에이전트는 부모 턴의 현재 권한 모드와 `/permissions`, `--yolo` 같은 실행
중 변경을 다시 적용받을 수 있다. 따라서 에이전트 TOML의 `read-only` 기본값은
Full access 부모 아래에서 강제 경계가 아니다. 이 기록의 권한 검증 결과는 제한된
저장 명령과 읽기 전용 부모를 사용한 흐름의 범위로 해석한다. 현재 사용 정책은

부모 읽기 전용은 추가 보호를 위한 선택이다. 두 승인 모드의 실제 부모·자식 권한과

[Codex 하위 에이전트 문서](https://learn.chatgpt.com/docs/agent-configuration/subagents)에
있다.

permission profile은 베타이고, 불러온 설정 중 하나라도 기존 `sandbox_mode`를
포함하면 기존 샌드박스 설정이 선택될 수 있다. 이번 회귀 테스트가 전용 설정
스택을 따로 둔 이유이며, Codex가 업데이트되면 공식
[권한 프로필 문서](https://learn.chatgpt.com/docs/permissions)와 실제 통합 테스트를

## 대화 저장의 긴 터미널 입력 · 2026-10-01

사용자가 확정한 대화 범위의 저장 시험에서 실패를 보고했다. 해당 Codex 도구 기록은
정확한 개인 실행기로 `save-conversation`을 시작한 뒤 긴 JSON을 PTY에 한 줄로 보내고,
입력 일부가 에코된 후 BEL·대기가 발생한 것을 보여준다. 일반 실행은 JSON 없이 EOF를
받아 빈 입력으로 종료됐다. 이후 Node 하위 프로세스 호출은
`sandbox-exec: sandbox_apply: Operation not permitted`로 종료됐다. 개인 명령 규칙은
존재했다. 최종 실패 안내만으로 최초 원인을 권한 설정 누락으로 판단하지 않는다.

합성 입력으로 실제 macOS PTY에서 같은 현상을 재현했다. 기본 canonical/echo 상태에서
12,045바이트 입력 중 11,021개의 BEL이 관측됐고 읽기가 8초 안에 끝나지 않았다.
실험 프로세스만 종료했으며 실제 연구 저장소나 원본 PDF를 바꾸지 않았다.

CLI의 텍스트 입력 함수가 터미널일 때 줄 단위 입력·에코·입력 변환을 해제하고,
준비가 끝나면 stderr로 `__RESEARCH_STORE_STDIN_READY__`를 출력하도록 수정했다.
호출자는 이 표시를 받은 뒤 JSON과 기존 종료 표시를 보낸다. 성공·입력 오류·Ctrl-C
중단에는 원래 터미널 설정을 복구한다. 파이프와 EOF·크기 제한은 유지했다.
실행기·프로필·개인 실행 규칙·모델 라우팅은 변경하지 않았다.

검증:

- PTY 원문 저장, CRLF·입력 바이트 보존, 잘못된 JSON/UTF-8, 크기 초과, 준비 실패,
  미지원 터미널, Ctrl-C 중단과 설정 복원 등 stdin 집중 10개 통과.
- 대화 관리 24개와 기존 CLI 파이프 2개를 포함한 개발자 집중 실행 36개 통과.
  별도 확인에서 stdin·대화 관리·제품 목록 검증 35개 통과.
- 폐기 가능한 설치본·HOME에서 실제 공개 개인 실행기와 `research-store` permission
  profile을 사용했다. **92,183바이트** 한글 JSON이 에코/BEL 없이 저장됐고 원문이
  정확히 일치했다. 설정 복구와 외부 합성 원본 파일의 쓰기 차단·해시 보존을 확인했다.
  임시 설치본은 테스트용 CLI 진입점을 사용했으므로 실제 신규 설치 전체를 시험한 것은
  아니다. 실제 개인 저장소에 쓰거나 모델을 호출하지 않았다.
- 버전·한영/웹 가이드 일치 검사 통과. 스킬 frontmatter는 그대로이며 참조 경로는
  제품 목록 검증에서 확인했다. 공용 `quick_validate.py`는 PyYAML이 없어 실행하지 못했다.

- 개발 프로젝트에서 최종 집중 회귀 78개 중 76개 통과·2개 건너뜀. 두 항목은
  `test_case_variant_pdfs_are_converted_to_distinct_markdown`과
  `test_colliding_legacy_document_paths_migrate_deterministically`이며, 현재 파일
  시스템이 대소문자만 다른 파일명을 보존하지 않아 건너뛰었다.
- Codex의 실제 `exec_command(tty: true)`와 `write_stdin`에서도 준비 표시를 받은
  뒤 28,711바이트 합성 JSON을 400문자 조각으로 전달해 저장·원문 일치를 확인했다.
  큰 단일 쓰기는 도구의 검토 크기 한도로 거부되어 작은 조각을 사용했다. 이 시험은
  임시 HOME을 환경으로 지정하고 개발용 외부 실행 승인을 받은 폐기용 설치본이다.
  실제 사용자 채팅의 기본 권한에서 개인 실행 규칙까지 다시 시험한 것은 아니다.
- 독립 검토에서 정상 경로와 권한 경계의 회귀는 발견하지 않았다. 강제 종료에
  터미널 설정 복구를 보장한다는 넓은 문구는 정상 종료·처리한 오류·Ctrl-C로
  한정했다. SIGTERM·SIGKILL에서는 복구가 보장되지 않는다.
- 현재 개인 설치본의 CLI·제품 정책 두 위치·대화 참조 두 파일을 이전 코드 보관 후
  갱신했다. 저장 자료 45개 파일의 내용과 수정 시각은 모두 유지했다. 개인 등록이나
  권한 프로필은 변경하지 않았고, 임시 시험 저장소는 제거했다.

사용자가 같은 확정 범위로 재시도한 뒤 제공한 완료 응답은
‘DistilBERT·MobileBERT 모바일 문장 분류 비교 실험 계획과 선택 기준’으로 저장하고
다시 조회했다고 보고한다. 선택한 대화 원문 4개와 요약, 최종 선택 기준이 포함됐다는
응답의 결과 부분을 [대화 저장 가이드 캡처](../../../site/assets/screenshots/conversation-save-result.png)로
남겼다. 이 확인은 사용자 제공 화면에 근거하며, 저장된 원문이나 DB를 독립 조회해
일치 여부를 검사한 것은 아니다. 범위 선택 화면과 후속 검색 활용은 아직 미확인이다.
